# RTL Design & Verification of Cache Controller with MSI Cache Coherence Protocol

Drashi Jain | Computer Architecture  | IIIT Delhi**


---

## Overview

This project implements and verifies an RTL model of a **cache controller** connected to a simulated CPU and an atomic snooping bus. Cache coherence is maintained using the **MSI (Modified-Shared-Invalid) protocol**. A simple main memory model serves as fallback when neither cache holds the requested line. The CPU signals are generated by a testbench — no actual CPU or bus hardware is required in the design.

The system consists of two L1 caches, each with its own cache controller, connected via a shared atomic bus to an L2/Memory Controller and DRAM.

## System Architecture

```
Simulated          ┌─────────────────────────────────────┐
Processor    ────► │  L1 Cache ──► Cache Controller       │
Signals            │                          │           │
             ────► │  L1 Cache ──► Cache Controller ──── BUS ──► L2/Memory Controller ──► DRAM
                   │                                      │
                   │         DUT (HDL Implementation)     │
                   └─────────────────────────────────────┘
```

> **DUT** = L1 Caches + Cache Controllers + Bus Arbiter
> Processor signals are generated by the testbench. L2/Memory Controller and DRAM are modeled as simple behavioral modules.

## Design Choices

| Parameter | Choice | Justification |
|---|---|---|
| Cache Size | Parameterizable | Configurable via top-level parameters |
| Line Size | Parameterizable | Set via `CACHE_LINE_SIZE` parameter |
| Associativity | N-way | Configurable `N_WAYS` parameter |
| Replacement Policy | LRU | LRU better approximates optimal replacement vs FIFO for general access patterns |
| Write Policy | Write-back + Write-allocate | Reduces bus traffic; only evicted dirty lines written to memory |
| Outstanding Requests | 1 per cache | No MSHRs required per spec |
| Coherence Protocol | MSI | Three-state protocol over atomic snooping bus |

## MSI Protocol

### States
| State | Meaning |
|---|---|
| **I (Invalid)** | Cache line not present or invalid |
| **S (Shared)** | Cache line present, clean, possibly shared with other caches |
| **M (Modified)** | Cache line present, dirty, exclusively owned |

### Cache Controller State Transitions

| Current State | Event | Action | Next State |
|---|---|---|---|
| I | CPU Load | Issue `GetS` on bus | IS^D |
| I | CPU Store | Issue `GetM` on bus | IM^D |
| IS^D | Own `Data` (from mem/cache) | Load data into cache | S |
| IM^D | Own `Data` | Store hit into cache | M |
| S | CPU Store | Issue `GetM` / Upgrade | SM^D |
| S | Other `GetM` (snoop) | Invalidate line | I |
| M | CPU Load/Store | Hit (no bus transaction) | M |
| M | Other `GetS` (snoop) | Send data to bus + memory, downgrade | S |
| M | Other `GetM` (snoop) | Send data to req, invalidate | I |
| M | Replacement | Issue `PutM`, send data to memory | I |

### Memory Controller State Transitions

| State | GetS | GetM | PutM |
|---|---|---|---|
| IorS | Send data to requestor/IorS | Send data to requestor/M | — |
| IorS^D | (A) — wait for data | (A) — wait for data | Update memory / IorS |
| M | Transition to IorS^D | — | Transition to IorS^D |

*(Reference: A Primer on Memory Consistency and Cache Coherence, 2nd Ed.)*

## How to Run

### Prerequisites
- [Icarus Verilog](http://iverilog.icarus.com/) (`iverilog`) — recommended
- [GTKWave](http://gtkwave.sourceforge.net/) — for waveform viewing
- Alternatively: Vivado / NCVerilog

### Compile & Simulate

```bash
# Clone the repo
git clone <repo-url>
cd cache_coherence_msi

# Run all tests using the provided script
chmod +x sim/run_sim.sh
./sim/run_sim.sh

# Or compile manually (example: coherence testbench)
iverilog -o sim/coherence_tb \
  rtl/top.v rtl/cache.v rtl/cache_controller.v \
  rtl/bus_arbiter.v rtl/memory_controller.v \
  tb/tb_coherence.v

vvp sim/coherence_tb

# View waveforms
gtkwave sim/waves/coherence_tb.vcd

All reused public code (cache subsystem modules only) is cited above and in inline comments. The MSI protocol FSM and all coherence logic are original implementations. All modifications to reused code are documented with `// MODIFIED:` comments in the source files.
